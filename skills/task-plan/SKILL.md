# 과제 계획

실제 과제의 README·기존 지침·최신 운영 규칙·남은 시간을 먼저 확인한다. 이 절차는 범용 참고 자료이며 해당 규칙을 바꾸지 않는다.

## 입력을 확인한다

- 제출 파일·실행 방법·시간 제한·필수 기능을 지시서에서 찾는다.
- 제공 데이터의 형식과 크기를 필요한 범위에서 확인한다. 전체 내용을 출력할 필요는 없다.
- 확인된 사실, 가정, 답이 필요한 질문을 분리한다.
- 구현을 바꿀 질문을 최대 3개씩 묶어 담당자에게 확인한다. 질문 수를 늘리는 것 자체를 목표로 삼지 않는다.

## 실행 가능한 계획을 만든다

1. 사용자와 해결할 문제를 한 문장으로 적는다.
2. 필수 요구마다 입력·기대 결과·확인 방법을 연결한다.
3. 필수 기능과 선택 기능을 구분한다. 요구된 기술이 없다면 현재 환경에 있고 본인이 이해하는 가장 단순한 구성을 선택한다.
4. 입력부터 결과까지 이어지는 핵심 흐름을 먼저 완성하는 순서를 정한다.
5. 위험한 가정·어려운 연결·결과 정확성부터 빠르게 확인한다.
6. 검증·설명·제출 시간을 미리 남긴다. 180분 과제에서 초기 계획은 보통 15~25분 안에 실행으로 연결하되 실제 난도에 맞춘다.

## 결과를 짧게 남긴다

목표 / 필수 조건 / 질문·가정 / 선택과 이유 / 첫 구현 범위 / 확인 방법 / 시간 계획을 남긴다. 양식이 이미 있으면 갱신한다. 문서 체계를 새로 여러 개 만들지 않는다.

계획이 바뀌면 달라진 조건과 영향만 갱신한다. 정답을 미리 알고 있거나 특정 점수를 보장하는 것처럼 쓰지 않는다. 계획 후에는 실제 구현을 진행한다.
