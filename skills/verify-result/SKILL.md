# 결과 검증

검증 대상과 실제 요구사항을 읽는다. 공식 제출 규칙과 허용 도구를 따른다. 이 Skill은 실제 검사를 대신하지 않는다.

## 확인할 위험을 선택한다

- 기능별 필수 조건과 관련된 실패를 우선한다.
- 코드의 현재 출력과 독립적으로 정답을 정할 수 있는 작은 사례를 만든다.
- 빈 입력, 누락, 중복, 잘못된 값, 범위 끝값 중 과제에 중요한 사례만 선택한다.
- 데이터 삭제·대체·필터·집계가 바뀌면 전후 건수와 결과 영향도 확인한다.
- 학습 과제라면 데이터 분리·누출·기준선·지표 계산부터 확인한다.

## 실제로 실행한다

1. 입력과 기대 결과를 먼저 기록한다.
2. 허용된 터미널 명령이나 수동 화면 확인으로 실제 동작을 확인한다.
3. 종료 코드와 출력·결과 파일을 대조한다. 실행 성공과 의미상 정확성을 구분한다.
4. 실패하면 원인 가설 하나를 좁혀 수정하고 같은 사례를 다시 실행한다.
5. 관련 기존 동작을 필요한 범위에서 재확인한다.

브라우저 자동화·Computer Use·외부 전송을 검증 수단으로 도입하지 않는다. 플랫폼의 허용 경계를 따른다.

## 근거를 보고한다

각 확인에 요구 ID / 입력 / 기대 결과 / 실행 방법 / 실제 결과 / 판정 / 한계를 남긴다. 실행하지 않은 것은 미실행 또는 미확인이다. 오류 메시지를 없앤 것만으로 해결됐다고 쓰지 않는다.

도구의 성공은 설정한 확인의 성공이다. 파일 존재나 해시가 같다는 사실은 기능 정답을 보증하지 않는다. 모든 위험이 해결됐다고 단정하지 말고 남은 위험의 영향과 다음 확인을 적는다.
