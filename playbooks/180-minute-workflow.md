# 180분 과제 진행

아래는 권장 시간 배분입니다. 실제 타이머와 제출 절차를 기준으로 조정합니다. 검증은 구현 중에도 계속 수행하고, 후반에 전체를 다시 확인합니다.

| 경과 시간 | 중심 작업 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| 0~15분 | 과제·제출 조건·파일 확인, 중요한 질문 | 누구의 어떤 문제를 풀지 설명 가능 |
| 15~25분 | 필수 범위와 완료 조건 결정 | 요구사항별 구현·확인 방법이 정리됨 |
| 25~85분 | 입력부터 출력까지 핵심 흐름 구현 | 실제 입력 하나로 전체 흐름이 동작함 |
| 85~120분 | 남은 필수 기능과 중요한 예외 처리 | 필수 조건을 하나씩 확인할 수 있음 |
| 120~145분 | 결과 정확성 확인, 중요한 오류 수정 | 핵심 결과와 실패 상황의 근거가 있음 |
| 145~165분 | 재실행, 문서, 구현 설명 점검 | 실행 방법·실제 상태·한계를 설명 가능 |
| 165~180분 | 최종 저장·제출·완료 확인 | 플랫폼에서 제출 완료를 직접 확인 |

## 1. 시작 시 확인할 것

- 실제 과제 README, 제공 지침, 실행 안내, 제출 파일명과 위치를 읽습니다.
- 원본 데이터의 위치와 변경 가능 여부를 확인합니다.
- 어떤 환경·라이브러리·모델이 이미 제공되는지 확인합니다.
- 결과 화면, 보고서, 실행 코드, 학습 파일 중 무엇을 제출해야 하는지 구분합니다.
- 불확실한 사항 중 구현을 바꾸는 질문만 먼저 확인합니다.

기존 프로젝트가 있다면 먼저 실행해 현재 상태를 파악합니다. 환경을 새로 만들거나 의존성을 바꾸는 일은 필요가 확인된 뒤 진행합니다.

## 2. 완료 조건을 정하는 방법

요구사항은 동작과 확인 방법을 함께 적습니다.

| 요구사항 예시 | 확인 방법 예시 |
|---|---|
| 지정한 파일을 읽는다 | 제공 파일과 형식 오류 파일을 각각 확인 |
| 합계를 정확히 계산한다 | 손으로 계산할 수 있는 작은 입력과 비교 |
| 조건을 바꾸면 결과가 바뀐다 | 서로 다른 조건 두 개의 기대 결과 확인 |
| 오류를 이해할 수 있게 알린다 | 빈 입력·누락 항목의 안내 확인 |

필수 조건, 시간이 남으면 할 조건, 이번에 하지 않을 범위를 구분합니다. 이후 새로운 아이디어가 나오면 먼저 필수 조건에 영향을 주는지 판단합니다.

## 3. 한 기능을 끝내는 짧은 반복

1. 사용자에게 필요한 동작을 확인합니다.
2. AI에 작업 범위와 완료 조건을 지정합니다.
3. 실제로 실행하고 기대 결과와 비교합니다.
4. 불일치가 있으면 재현 가능한 작은 사례를 만듭니다.
5. 수정 후 같은 사례와 인접한 핵심 기능을 다시 확인합니다.
6. 중요한 결정·확인 결과·남은 문제만 기록합니다.

AI가 완료했다고 보고한 사실과 실행으로 확인한 사실을 구분합니다. 문서의 완료 표시도 실제 확인 결과에 맞춥니다.

## 4. 진행이 늦을 때

선택 기능과 장식을 줄이고 필수 흐름을 유지합니다. 새로운 기술 도입·대규모 구조 변경은 남은 시간 대비 이익을 판단합니다.

남은 작업의 우선순위:

1. 실행·제출을 막는 문제
2. 누락된 필수 조건
3. 잘못된 결과를 만드는 핵심 오류
4. 중요한 예외와 검증 부족
5. 실행 설명과 본인 이해의 부족
6. 선택 기능과 화면 다듬기

## 5. 제출 직전

- 지정된 제출 위치와 파일명이 맞는지 확인합니다.
- 실제 사용하는 데이터·설정·실행 파일이 준비됐는지 확인합니다.
- 실행 안내를 따라 다시 실행해 핵심 흐름을 확인합니다.
- 확인하지 않은 부분은 미확인으로 남깁니다.
- 설명할 수 없는 자동 생성 코드가 핵심 기능에 남아 있지 않은지 읽습니다.
- 최종 저장과 플랫폼의 제출 완료 확인에 시간을 남깁니다.

파일 검사는 플랫폼 제출을 대신하지 않습니다. 최종 제출 버튼과 완료 상태는 실제 화면 안내에 따릅니다.
