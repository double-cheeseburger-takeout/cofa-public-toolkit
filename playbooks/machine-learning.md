# 예측·분류·모델 활용 과제

머신러닝은 데이터에서 규칙을 학습해 새 입력의 결과를 예측하는 방법입니다. 과제가 모델 학습을 요구하는지, 이미 제공된 모델을 활용하는지, 단순 규칙으로 충분한지 먼저 확인합니다.

## 1. 문제와 데이터 정의

- 입력 한 건이 무엇인지 설명합니다. 예: 표 한 행, 이미지 한 장, 문장 한 개.
- 정답이 무엇인지 확인합니다. 예: 수치, 범주, 이미지의 결함 영역.
- 예측을 사용해 어떤 판단을 할지 확인합니다.
- 허용된 데이터·모델·학습 시간·외부 호출 범위를 확인합니다.
- 먼저 작은 기준 방법으로 실행과 평가 과정을 연결합니다.

기준 방법은 복잡한 모델의 개선 여부를 비교하는 출발점입니다. 회귀에서는 평균값 예측, 분류에서는 가장 많은 범주 예측을 참고할 수 있지만, 실제 과제에 맞는 기준을 선택해야 합니다.

## 2. 데이터 누출 방지

데이터 누출은 실제로 예측할 때 알 수 없는 정보가 학습이나 평가에 섞여 성능이 과장되는 문제입니다.

- 학습에 쓴 데이터와 최종 확인용 데이터를 구분합니다.
- 같은 사람·장비·제품에서 나온 유사한 자료가 양쪽에 섞이지 않아야 하는지 확인합니다.
- 미래를 예측하는 문제라면 시간 순서를 고려합니다.
- 평균·표준편차를 이용한 전처리는 학습 데이터로 기준을 정한 뒤 나머지에 적용합니다.
- 평가 결과를 보고 계속 조정했다면 그 데이터는 완전히 독립적인 최종 평가가 아닙니다.
- 정답에서 만들어진 열이나 결과 발생 후에만 알 수 있는 열을 입력으로 넣지 않습니다.

## 3. 지표 선택

지표는 모델을 어떤 기준으로 잘했다고 판단할지 정하는 숫자입니다. 과제에서 지정한 지표가 있으면 우선 따릅니다.

| 목적 | 지표 예 | 뜻과 주의점 |
|---|---|---|
| 수치 오차 | MAE | 예측과 정답 차이의 절댓값 평균. 원래 단위로 설명 가능 |
| 큰 오차를 더 강하게 반영 | RMSE | 오차를 제곱해 평균 낸 뒤 제곱근을 취한 값 |
| 전체 정답 비율 | Accuracy | 맞힌 비율. 한 범주가 매우 많으면 오해하기 쉬움 |
| 양성으로 예측한 것의 정확성 | Precision | 양성이라고 한 것 중 실제 양성의 비율 |
| 놓친 양성을 줄이기 | Recall | 실제 양성 중 찾아낸 비율 |
| 정밀도와 재현율 균형 | F1 | Precision과 Recall을 함께 반영한 값 |
| 각 범주를 같은 중요도로 보기 | Macro-F1 | 범주별 F1을 동일한 비중으로 평균 |
| 영역 겹침 | IoU, Dice | 예측 영역과 정답 영역이 얼마나 겹치는지 비교 |

분모가 0인 경우의 처리와 범주별 표본 수를 확인합니다. 높은 숫자 하나만으로 모든 실패를 설명하지 않습니다.

## 4. 제한 시간 안의 구현

1. 입력·정답 형식과 작은 데이터 묶음의 크기를 확인합니다.
2. 학습 또는 추론 한 번을 실행합니다.
3. 출력 형태와 손실·지표 계산이 맞는지 확인합니다.
4. 기준 결과를 저장한 뒤 한 번에 중요한 조건 하나를 바꿉니다.
5. 개선과 실행 비용을 비교해 다음 변경을 결정합니다.

시드(seed)는 난수 생성의 시작값입니다. 비교를 재현하기 위해 시드와 데이터 분리 방법을 기록하되, 모든 환경에서 완전히 같은 결과가 보장된다고 단정하지 않습니다.

## 5. 반드시 확인할 것

- 입력 크기와 출력 크기가 목적에 맞는가?
- 정답 범주 번호와 모델 출력의 대응이 맞는가?
- 평가 단계에서 학습 전용 동작이 남아 있지 않은가?
- 학습 데이터가 평가 계산에 잘못 섞이지 않았는가?
- 성능이 낮은 사례를 직접 몇 개 확인했는가?
- 모델을 저장한 뒤 다시 불러와 결과를 낼 수 있는가?
- 실행 시간·메모리 사용이 주어진 환경에 맞는가?

## 6. 설명 준비

입력 → 전처리 → 모델 → 출력 → 평가의 순서를 설명합니다. 선택한 모델의 이유, 기준 방법과의 차이, 데이터 분리 방식, 자주 실패하는 사례, 확인한 실행 비용을 실제 기록에 맞춰 답합니다.

대규모 학습이나 새로운 모델 도입은 과제 요구와 남은 시간으로 판단합니다. 제공된 환경의 모델·도구 제한이 이 문서보다 우선합니다.
