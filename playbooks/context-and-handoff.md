# 맥락 유지와 인수인계

인수인계는 다른 사람이나 다른 AI 세션이 현재 상태를 이해하고 다음 작업을 시작할 수 있게 정리하는 것입니다. 긴 대화를 모두 복사하기보다 현재 판단에 필요한 내용을 남깁니다.

## 언제 정리할까?

- 목표나 우선순위가 바뀌었을 때
- 큰 기능 하나를 완료했을 때
- AI가 이미 정한 제약을 놓치기 시작했을 때
- 작업을 다른 역할·세션에 맡길 때
- 제출 전에 실제 상태를 확인할 때

## 최소 인수인계 내용

1. **목표와 필수 조건:** 무엇을 끝내야 하는가?
2. **현재 상태:** 무엇이 구현됐고 무엇이 실제 확인됐는가?
3. **중요한 결정:** 왜 현재 방향을 택했는가?
4. **파일 위치:** 핵심 입력·처리·출력·실행 안내는 어디에 있는가?
5. **남은 문제:** 어떻게 재현되며 영향은 무엇인가?
6. **다음 행동:** 가장 먼저 할 한두 가지는 무엇인가?
7. **제약:** 변경하면 안 되는 조건과 남은 시간은 무엇인가?

상세 양식이 필요하면 [HANDOFF.md](../templates/HANDOFF.md)를 사용합니다. 평소에는 [WORKLOG.md](../templates/WORKLOG.md)의 현재 상태만 갱신해도 됩니다.

## 여러 AI 역할을 나눌 때

| 역할 | 적절한 범위 | 반환해야 할 것 |
|---|---|---|
| 구현 | 서로 겹치지 않는 기능·파일 | 변경 내용, 실행한 검사, 남은 문제 |
| 검토 | 읽기와 오류 재현 중심 | 근거 위치, 영향, 확인 방법 |
| 문서 | 실제 구현과 실행 기록 정리 | 사실에 맞는 실행·제출 안내 |

동일한 파일을 여러 역할이 동시에 바꾸지 않도록 범위를 정합니다. 독립 작업이 없다면 역할만 바꾸어 순서대로 검토해도 됩니다. 에이전트를 늘리는 것 자체가 목표는 아닙니다.

## 새 세션에서 복구할 때

1. 실제 과제 지침과 현재 메모를 읽게 합니다.
2. 핵심 파일과 실행 상태를 다시 확인하게 합니다.
3. 메모와 실제 코드가 다르면 차이를 먼저 정리합니다.
4. 다음 작업 한 가지부터 이어갑니다.

과거 세션의 성공 보고를 실행 사실로 무조건 이어받지 않습니다. 특히 파일이 변경된 뒤에는 필요한 검사를 다시 수행합니다.

세션 전환 방법과 제공된 모델은 현재 환경의 안내를 따릅니다. 이 문서를 사용하기 위해 Codex 업데이트나 관리 설정 변경이 필요하지는 않습니다.
