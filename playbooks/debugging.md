# 오류를 줄이는 디버깅

디버깅은 잘못된 동작을 재현하고 원인을 찾아 수정하는 과정입니다. 오류 메시지를 없애는 것과 기대한 결과가 나오는 것을 모두 확인합니다.

## 1. 먼저 실패를 작게 만들기

다음 정보를 모읍니다.

~~~text
실행한 명령 또는 사용자 행동:
입력:
기대 결과:
실제 결과:
오류 메시지:
마지막으로 정상 동작한 상태:
직전 변경:
~~~

오류 메시지에 키·토큰 등이 있으면 공유하거나 공개 문서에 적지 않습니다. 문제 자료는 시험 작업 공간 안에서 다룹니다.

## 2. 원인 후보를 좁히기

| 증상 | 먼저 확인할 범위 |
|---|---|
| 실행 자체가 안 됨 | 경로, 실행 명령, 의존성, 문법, 필수 설정 |
| 입력을 못 읽음 | 파일 위치, 인코딩, 형식, 열 이름 |
| 결과가 틀림 | 단위, 자료형, 경계 조건, 집계·정렬·인덱스 |
| 화면만 안 바뀜 | 요청 결과, 상태 갱신, 표시 조건 |
| 일부 입력만 실패 | 정상·실패 입력의 차이 |
| 너무 느림 | 반복 횟수, 불필요한 재계산, 데이터 크기, 외부 대기 |

모든 후보를 한꺼번에 고치지 않습니다. 관찰로 구분할 수 있는 후보를 먼저 확인합니다.

## 3. 작은 변경 후 재검증

1. 원인 후보를 하나 정합니다.
2. 그 후보가 맞는지 확인할 관찰이나 작은 검사를 수행합니다.
3. 필요한 범위만 수정합니다.
4. 처음 실패한 입력을 다시 실행합니다.
5. 가까운 정상 사례도 확인합니다.
6. 확인한 원인과 수정 결과를 짧게 남깁니다.

같은 실패가 반복되면 새 수정안을 연속으로 적용하기 전에 현재 가정부터 다시 확인합니다. 실행하지 않은 AI의 설명만으로 원인이 확정됐다고 기록하지 않습니다.

## 4. 시간이 부족할 때

- 필수 기능을 막는 문제부터 처리합니다.
- 해결 비용이 큰 선택 기능은 범위를 줄일 수 있는지 판단합니다.
- 마지막 정상 상태로 돌아갈 때는 본인 변경과 제공 파일을 구분합니다.
- 문제를 덮기 위해 예외를 모두 무시하거나 성공으로 표시하지 않습니다.
- 해결되지 않은 문제는 재현 조건·영향·현재 대응을 남깁니다.

## 5. AI 요청 예시

~~~text
다음 실패를 재현하고 원인을 좁혀주세요.
기대 결과: [...]
실제 결과: [...]
재현 방법: [...]

현재 코드와 실행 근거를 먼저 확인하고, 원인 후보를 구분할 최소 검사를 제안해주세요.
원인이 확인되면 필요한 범위만 수정하고 처음 실패한 사례와 관련 정상 사례를 다시 확인해주세요.
추정한 내용과 실행으로 확인한 내용을 구분해주세요.
~~~
