# 오프라인 점검 도구

Python 3.9 이상과 기본 제공 모듈만 사용합니다. 추가 패키지 설치는 필요하지 않습니다. Python 자체가 제공되지 않는 환경에서는 설치를 시도하기보다 해당 작업을 제공 도구로 수행하십시오. 아래 `python3`는 환경에 따라 `python`으로 표시될 수 있습니다.

도구는 운영체제의 보안 격리 장치가 아닙니다. 실제 과제 안내와 제공 환경의 허용 범위를 우선합니다. 외부 전송, 모델 호출, 브라우저 자동화, Codex 갱신, 패키지 설치는 내장하지 않았습니다. **`run_checks.py`에 넣은 명령 자체의 동작은 별도 확인해야 합니다.**

## 공통 사용 원칙

- 아래 예제는 **이 저장소의 루트 폴더에서 실행**합니다. 실제 과제 폴더는 `--project`로 명시합니다.
- `--project`를 받는 명령의 내부 대상 경로는 그 프로젝트 기준입니다. 설정 파일 경로와 `--output` 경로는 터미널의 현재 폴더 기준입니다.
- `--output`을 생략하면 결과를 터미널에 JSON으로 표시합니다. JSON은 항목 이름과 값을 구조적으로 저장하는 텍스트 형식입니다.
- `--output`은 **새 파일만 생성**합니다. 같은 이름의 이전 결과를 덮어쓰지 않습니다. 출력할 상위 폴더는 미리 존재해야 합니다.
- 보고서는 문제·실행 결과를 포함할 수 있습니다. 시험 환경 안에서 보관하고 공개 저장소로 보내지 마십시오.
- 종료 코드 `0`은 해당 도구가 정한 확인이 완료됐다는 뜻입니다. `1`은 검사 실패·일부 이상 발견, `2`는 설정·입력·파일 처리 오류입니다. 점수나 전체 정답을 의미하지 않습니다.

## 1. 실행 환경 확인 — `env_report.py`

```bash
python3 scripts/env_report.py
```

운영체제·Python 버전과 Git, Node, npm의 설치 여부·버전만 확인합니다. 환경 변수와 인증 파일은 읽지 않습니다. 없는 프로그램은 설치하지 않습니다. 버전 확인이 실패하면 그 사실을 출력합니다.

## 2. CSV 진단 — `csv_profile.py`

```bash
python3 scripts/csv_profile.py examples/tiny_sales.csv
python3 scripts/csv_profile.py examples/tiny_sales_invalid.csv
```

두 번째 명령은 열 수가 다른 행이 있으므로 종료 코드 `1`이 정상적인 관찰 결과입니다.

확인 항목: 열 수, 확인한 행 수, 빈 값, 행마다 열 수가 맞는지, 완전히 같은 행의 반복 횟수, 숫자로 읽을 수 있는 값의 최솟값·최댓값·합계·평균입니다. 데이터는 수정하지 않습니다.

```bash
python3 scripts/csv_profile.py /path/to/task/data.tsv --delimiter "\t" --encoding utf-8-sig --max-rows 200000
```

- 기본 인코딩 `utf-8-sig`는 UTF-8과 UTF-8 BOM 파일을 읽습니다. BOM은 파일 앞에 붙는 인코딩 표시입니다. 다른 인코딩은 `--encoding`으로 명시하십시오.
- 기본 최대 확인 행 수는 100,000입니다. 제한에 걸리면 전체 파일을 확인한 것처럼 표시하지 않고 `scan_limit_reached`를 기록합니다.
- 빈 문자열·공백만 누락값으로 셉니다. `NA`, `null`, `0`의 의미는 자동 판단하지 않습니다.
- 열 수가 맞지 않는 행은 별도로 세고 열별 통계에서 제외합니다.
- 숫자 통계는 28자리 정밀도의 십진수 계산이며 JSON에는 문자열로 저장합니다. 식별번호가 숫자처럼 보인다고 측정값이라고 판단하지 않습니다.
- 계산할 수 있는 십진수 범위를 넘어선 값은 별도 개수와 경고로 표시하고 숫자 통계에서 제외합니다.
- 중복이 반드시 오류인 것은 아닙니다. 제거할지 여부는 업무 규칙을 확인해야 합니다.
- 날짜의 유효성, 업무 공식, 파일 전체의 의미적 정확성은 별도 검사해야 합니다.
- 종료 코드가 0이어도 `warnings`와 `scan_limit_reached`를 함께 확인하십시오. 모든 경고를 검사 실패로 처리하는 도구는 아닙니다.

## 3. 실제 검증 명령 기록 — `run_checks.py`

도구 자체의 예제 테스트:

```bash
python3 scripts/run_checks.py --project . --config examples/checks.example.json
```

**위 결과는 도구 모음의 시험 결과입니다. 자신의 과제 결과물을 검증한 기록으로 사용하지 마십시오.**

실제 과제에 사용할 설정은 `checks.project.template.json`을 제공 작업 공간에 복사한 뒤 `checks`를 채웁니다. 아래는 형식 예시입니다. `tests`라는 경로와 실행 명령은 실제 프로젝트에 맞게 바꿔야 합니다.

```json
{
  "checks": [
    {
      "name": "my_required_behavior_tests",
      "argv": ["{python}", "-m", "unittest", "discover", "-s", "tests", "-v"],
      "cwd": ".",
      "timeout_seconds": 30
    }
  ]
}
```

- `argv`는 실행 파일과 각 인수를 나눈 배열입니다. 셸의 한 줄 문자열이 아닙니다. `&&`, 리다이렉션, 환경 변수 치환은 자동 해석되지 않습니다.
- `{python}`은 현재 도구를 실행한 Python으로, `{project}`는 지정 프로젝트 경로로 치환됩니다. 배열 항목 전체가 정확히 해당 표기일 때만 치환합니다.
- `cwd`는 각 명령을 실행할 프로젝트 내부 폴더이며 기본값은 `.`입니다.
- 기본 제한 시간은 명령당 30초입니다. 제한 시간을 넘기면 통과가 아닌 `timed_out`으로 기록합니다.
- 명령별 실제 종료 코드, 출력, 걸린 시간을 기록합니다. 큰 출력은 앞·뒤를 보존하고 잘렸다는 표시를 붙입니다.
- 빈 검사 목록, 실행할 수 없는 명령, 실패한 명령을 통과로 처리하지 않습니다.
- 백그라운드 서버를 시작하는 명령 대신 종료되는 테스트 명령을 넣으십시오. POSIX 계열에서는 시간초과 시 같은 프로세스 그룹을 종료하며, Windows에서는 직접 실행한 프로세스만 종료할 수 있습니다.
- 이 도구는 사용자가 고른 검사만 실행합니다. 검사의 기대값과 범위가 옳은지 직접 검토해야 합니다.

## 4. 파일 목록과 내용 확인값 — `artifact_manifest.py`

```bash
python3 scripts/artifact_manifest.py --project .
```

파일의 프로젝트 내부 상대 경로·바이트 크기·SHA-256 값을 출력합니다. SHA-256은 파일 내용이 같은지 대조할 때 쓰는 값입니다. 파일을 묶거나 전송하지 않습니다.

Git 내부 폴더, 가상환경, `node_modules`, Python 캐시, `.env` 및 `.env.*` 설정 파일, `work-output`을 기본 제외합니다. 심볼릭 링크는 파일·폴더 모두 따라가지 않습니다. 심볼릭 링크는 다른 경로를 가리키는 연결 항목입니다.

이 목록은 실행의 정확성이나 제출 수신을 확인하지 않습니다. 기본 제외 목록만으로 모든 민감정보를 탐지할 수도 없습니다.

## 5. 필수 파일 확인 — `check_deliverables.py`

```bash
python3 scripts/check_deliverables.py --project . --config examples/deliverables.example.json
```

설정의 `required` 배열에 실제 과제에서 요구한 경로를 적습니다. `kind`는 `file` 또는 `directory`이고, `nonempty`는 비어 있으면 안 되는지의 여부입니다.

```json
{
  "required": [
    {"path": "YOUR_REQUIRED_FILE.py", "kind": "file", "nonempty": true}
  ]
}
```

`YOUR_REQUIRED_FILE.py`는 형식 설명용 자리표시자입니다. 과제에서 요구한 이름으로 바꿉니다. 실제 대회에서 이 이름을 요구한다고 가정하지 마십시오.

파일 존재·종류·빈 파일 여부만 확인합니다. 정답, 기능, 숨겨진 채점 항목, 플랫폼 제출 완료 여부는 확인하지 않습니다.

## 6. 기록 양식 하나 생성 — `init_notes.py`

```bash
python3 scripts/init_notes.py --project /path/to/task
```

선택한 작업 공간에 `WORKLOG.md`를 새로 만듭니다. 기존 파일은 덮어쓰지 않습니다. 다른 이름이 필요하면 `--filename MY_WORKLOG.md`를 지정합니다. 과제에서 허용하는 작업 경로를 사용하고 실제 확인한 내용만 채우십시오.

## 자체 테스트

```bash
python3 -m unittest discover -s tests -v
```

합성 입력과 임시 폴더를 사용해 도구의 실패·시간초과·경로 이탈·덮어쓰기 방지 등을 확인합니다. 외부 서비스와 대회 접속 환경을 시험한 것은 아닙니다.
